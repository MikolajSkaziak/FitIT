# UX Profile

Updated on 2026-10-06 to the direction the author accepted after four rounds of mock-ups. The mock-ups in `docs/design` (pages, PNGs and `gen_design.py`) are the visual source of truth; this file states the same rules as tokens. All UI/UX skills in this project read this file before changing layout, copy, or interaction. The Polish summary for humans is section 10.1 of `docs/FitIt_Specyfikacja_MVP.md`.

## Platform

- Native mobile app: Expo / React Native, iOS and Android phones. There is no CSS. Every rule below is expressed as React Native style tokens exported from `mobile/src/theme`.
- The skills are written for the web. Apply their intent, not their syntax: `:hover` becomes the pressed state, tooltips and `aria-label` become `accessibilityLabel`, `kbd` hints and `/` shortcuts do not exist, `backdrop-filter` is not used.
- Only one viewport class exists: narrow. Use the **Narrow** line of each `page-patterns` entry and the 375 px case of `viewports`. Respect safe areas and the keyboard.

## Aesthetic reference

- **Standard:** Custom
- **Notes:** One colour, sage, on quiet neutrals; calm, premium, minimalist, but not black-and-white. Content sits directly on the page; a box is the exception. Apple Native for density, hit targets and motion. The author rejected, in order: a monochrome look, a lilac look with six tints, and a three-colour look (sage, blue, sand). Do not bring any of them back.

## Tokens

Token names are the keys of the theme object. Use tokens only; no literal colours, sizes or durations in components.

### Colour

Contrast figures are computed WCAG ratios; every pair below passes AA (checked by `docs/design/gen_design.py`).

| Token | Light | Dark | Use |
| --- | --- | --- | --- |
| `canvas` | `#F5F7F3` | `#121815` | Screen background |
| `surface` | `#FFFFFF` | `#1B2320` | Cards, inputs, sheets' inner cards, tab bar |
| `text` | `#1F2A25` | `#ECF0EB` | Primary content, weather glyph line |
| `textSecondary` | `#57625C` | `#A5AFA8` | Secondary text and meta |
| `border` | `#E1E6DF` | `#2A342F` | Hairlines, card frames, progress track |
| `borderControl` | `#838A84` | `#6E7972` | Input and idle option outlines; at or above 3:1 |
| `action` | `#2F5D4C` | `#A8D2BD` | Primary button, links, progress, active tab, accent word in a headline, selection ring and check |
| `onAction` | `#FFFFFF` | `#10201A` | Text and icons on `action` |
| `sage` | `#DCE7DA` | `#22362D` | Selected fill, the one emphasis panel, proposal tab, filter chip |
| `onSage` | `#2B5846` | `#A8D2BD` | Titles and icons on `sage` |
| `well` | `#DCE7DA` | `#C3D1C4` | Backdrop of every garment and silhouette photo; stays light in dark mode so dark clothes show |
| `skeleton` | `#E7ECE5` | `#252E29` | Loading placeholders |
| `disabledFill` / `disabledText` | `#E1E6DF` / `#57625C` | `#2A342F` / `#A5AFA8` | A control that cannot act yet, always next to a visible reason |
| `danger` / `onDanger` | `#A33B3B` / `#FFFFFF` | `#F2A3A3` / `#2A0E0E` | Destructive actions and errors only |
| `scrim` | `rgba(31,42,37,0.5)` | `rgba(0,0,0,0.6)` | Behind sheets and dialogs |

- No other hue anywhere: no blue, sand, violet or per-item tints.
- Follow the system colour scheme. Verify every changed screen in both schemes.

### Elevation

- Canvas; surfaces carry a 1 px `border`; sheets and dialogs are `canvas` with a 1 px `border` over `scrim`. No shadows, no blur, no gradients.
- Garments always sit on a `well` tile. An outfit is a plain grid of such tiles with no frame around it.
- Lists of settings are surfaces with hairline dividers. Weather, the wardrobe-use line and the profile header have no box.

### Type

Headings: Bricolage Grotesque 600. Text: Figtree 400 and 600. No other weights or families.

| Token | Size / line height | Family and weight | Use |
| --- | --- | --- | --- |
| `meta` | 12 / 16 | Figtree 400 (600 for tab labels) | Timestamps, helper text, counts. Never primary content |
| `secondary` | 14 / 21 | Figtree 400 or 600 | Supporting text, tile captions, field labels, option labels |
| `body` | 16 / 24 | Figtree 400 | Default content, form values |
| `label` | 16 / 24 | Figtree 600 | Buttons, emphasised lines |
| `subheading` | 19 / 24 | Bricolage 600, tracking -0.01em | Section headings |
| `heading` | 23 / 28 | Bricolage 600, tracking -0.01em | Titles inside content, sheet titles |
| `display` | 33 / 38 | Bricolage 600, tracking -0.02em | The one large title of a screen; temperature |
| `logo` | 48 / 52 and 28 / 34 | Bricolage 600 | Wordmark "Fit" + "It", the second part in `action` |

- At most five sizes on one screen. Nothing below 12. Numbers use tabular figures.
- A headline may carry one accent word in `action`; never a second typeface.
- Respect the system font scale up to 1.3 times; layouts must not clip at that scale.

### Spacing and shape

- Spacing tokens: 4, 8, 12, 16, 24, 32, 48, 64. Screen gutter 16; top inset 52 under the status bar; gap between sections 24; inside a group 8 or 12.
- Controls are 48 high (44 compact); option tiles 56; no touch target below 44 by 44.
- One radius rule: controls (buttons, inputs, option tiles, segmented control) 10; cards 16; garment tiles 12 (8 for thumbnails and outfit miniatures); sheets and dialogs 20. Fully rounded only for the proposal tabs and filter chips.
- Bars (progress, step indicator, sheet grabber) are 4 high.
- Reserve space for content that loads later (images, counts) so nothing shifts.

### Motion

- Durations: 100, 150, 200 and 300 ms only. 100 for press feedback, 150 for exits, 200 for enters, 300 only for sheets.
- Easing: enter `cubic-bezier(0.16, 1, 0.3, 1)`, exit `cubic-bezier(0.7, 0, 0.84, 0)`. No springs with overshoot, no bounce.
- Animate opacity and transform only. Press feedback is a scale to 0.97.
- Motion must have a reason: a proposal entering, visualization progress, feedback to a touch. No decorative loops.
- When the system "reduce motion" setting is on, replace movement with an instant change or an opacity fade.

## Banned anti-aesthetics

- Any hue besides sage and bottle green (danger red excepted); per-item or per-category tints; rainbow grids
- Glassmorphism or blur; gradients; shadows; neon or glowing borders
- Pill-shaped buttons; pills or badges around ordinary metadata; decorative icon chips
- Boxes around things that read fine without one (weather, single lines of status)
- Decorative blob or mesh backgrounds; nested scroll regions
- Cartoon people in empty states; a large centred illustration with no action
- Icons inside inputs unless functional (search, clear, password reveal, date picker)
- A disabled primary action as the only feedback; it must sit next to a visible reason
- Serif type; Inter, Roboto or Open Sans; weights other than 400 and 600
- Emoji anywhere in the interface; hand-drawn icon paths; icon sets other than the recorded one
- Em dashes and en dashes in interface copy; slogans; invented numbers
- A circular spinner as the only loading state for content that takes longer than a second

## Accessibility target

- **Level:** WCAG 2.1 AA
- **Contrast:** at least 4.5:1 for text, 3:1 for large text and for control outlines. Do not introduce a new colour pair without computing its ratio.
- **Touch / focus:** targets at least 44 by 44. Every pressable element has an `accessibilityLabel` and role. Reading order follows visual order. Colour is never the only carrier of state: a selected option has a ring and a check, the active tab has a bar.

## Brand tone and microcopy voice

- **Voice:** Warm & Humancentric
- **Capitalization:** Sentence case for UI copy and buttons
- **Notes:** Interface language is Polish. Plain, specific, friendly; no jargon. Buttons start with a verb and name the outcome ("Zaproponuj zestawy", "Dodaj ubrania", "Pokaż na sylwetce", "Zakładam to"); never "OK" or "Wyślij" alone. One action has one name everywhere in the app. Errors never blame the person and always offer a way out. Do not address the user with gendered verb forms, even though the profile stores gender.

## Icon library

- **Library:** Phosphor
- **Package / path:** `phosphor-react-native`
- **Notes:** Weight `bold` for interface icons, sizes 20 and 24. Weather glyphs use weight `duotone` at 80 (56 in lists) with the line in `text` and the fill in `sage`: Sun, CloudSun, Cloud, CloudRain, CloudSnow. State is shown by colour plus a second cue, not by a second weight.

## Agent rules

1. Read this profile and open the matching page in `docs/design/ekrany` before creating or editing any screen, style or microcopy.
2. Prefer skills by task: new screen → `page-patterns` (name the pattern before markup); forms → `forms` and `labels`; sheets, inline edits and destructive actions → `surfaces`; loading → `loaders`; empty views → `empty-states`; copy → `verbs` and `errors`; motion → `motion`, `transitions`, `reduced-motion`. Before finishing UI work, run `ux-audit` and `anti-slop`.
3. Use only the recorded icon library. Do not mix icon sets or use emoji as UI icons.
4. Never introduce items on the banned list.
5. Destructive actions always use an explicit confirmation that names what will be removed.
6. When sources disagree, the order is: platform constraints and the accessibility target; the mock-ups in `docs/design`; this profile; the VectorLab skill for the task; `design-taste-frontend` (which applies in full only to the promotional website).
