# Cloudflare R2: magazyn zdjęć

Zdjęcia ubrań i gotowe wizualizacje leżą w Cloudflare R2. Backend rozmawia z nim protokołem S3, tym samym kodem
(`S3ImageStorage`), którym lokalnie rozmawia z kontenerem `storage`. Przejście z jednego na drugi to zmiana ustawień,
nie zmiana kodu.

Dlaczego R2, a nie Amazon S3: nie ma opłat za ruch wychodzący, a telefon pobiera każde zdjęcie ubrania przy każdym
otwarciu szafy. Przy darmowym progu 10 GB i rachunku za transfer równym zeru beta na kilkanaście osób nic nie kosztuje.

## Stan na 7 października 2026

**R2 nie jest jeszcze włączone na koncie.** Próba wylistowania kubełków przez API zwraca:
`10042 Please enable R2 through the Cloudflare Dashboard`. Do włączenia potrzebne jest wejście do panelu
i zaakceptowanie warunków R2; Cloudflare prosi przy tym o dane rozliczeniowe, mimo że próg darmowy nie wymaga opłat.
Dopóki tego nie zrobisz, cały kod działa na lokalnym kontenerze i nic nie jest zablokowane.

## Co zrobić, kiedy będziemy podłączać prawdziwe usługi

1. W panelu Cloudflare wejdź w **R2** i włącz usługę.
2. Załóż kubełek **z jurysdykcją Unii Europejskiej**. To nie jest to samo co zwykły kubełek: jurysdykcję wybiera się
   przy zakładaniu i nie da się jej potem zmienić. Polityka prywatności obiecuje, że pliki zostają w UE, więc to warunek,
   nie preferencja. Nazwa: `fitit`.
3. W **R2 → API → Manage API Tokens** utwórz token typu **Object Read & Write**, zawężony do tego jednego kubełka.
   Dostaniesz `Access Key ID` i `Secret Access Key`. Secret pokazuje się **raz**.
4. Skopiuj **Account ID** (jest na stronie R2 w panelu bocznym).
5. Ustaw na serwerze, w pliku środowiskowym poza repozytorium:

   ```
   Storage__AccountId=<account id>
   Storage__Jurisdiction=eu
   Storage__Bucket=fitit
   Storage__AccessKey=<access key id>
   Storage__SecretKey=<secret access key>
   ```

   `Storage__Endpoint` zostaw pusty. API samo złoży adres `https://<account>.eu.r2.cloudflarestorage.com`.
   `Storage__CreateBucket` zostaw wyłączone: kubełek zakładamy ręcznie, raz.

6. Sprawdź, że działa: po starcie API dodaj jedno ubranie z telefonu. Jeśli adres do wysyłki zwraca 403, token nie ma
   prawa zapisu albo jest zawężony do innego kubełka.

## Czego nie da się zrobić inaczej

- **Podpisane adresy działają tylko na domenie S3** (`<account>.r2.cloudflarestorage.com`). Nie da się ich wystawić
  z własnej domeny. Dlatego w produkcji `Storage__PublicEndpoint` zostaje pusty: telefon łączy się z tą samą domeną
  co backend. Osobny adres publiczny jest tylko po to, żeby lokalnie telefon trafił do kontenera innym adresem
  niż API.
- **Kubełek zostaje prywatny.** Dostęp jest wyłącznie przez podpisane adresy ważne godzinę (odczyt) i pięć minut
  (wysyłka). Publiczny kubełek wystawiłby wszystkie zdjęcia ubrań każdemu, kto zgadnie klucz.
- **Jurysdykcji nie zmienia się po fakcie.** Pomyłka oznacza założenie drugiego kubełka i przeniesienie plików.

## Co to zmienia w kodzie

Nic poza ustawieniami. `StorageOptions` przyjmuje `AccountId` i `Jurisdiction` i składa z nich adres, kiedy
`Endpoint` jest pusty. Reszta, czyli podpisywanie adresów, sprawdzanie wysłanego pliku, kasowanie i listowanie,
jest wspólna dla R2 i dla serwera lokalnego. Klient ma ustawione `ForcePathStyle` oraz liczenie sum kontrolnych
tylko tam, gdzie wymaga tego protokół, bo nowsze domyślne ustawienia pakietu AWS odrzuca zarówno R2, jak i versitygw.
